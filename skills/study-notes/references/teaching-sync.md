# Notes during learning

This guide is optional for standalone note work. When local learning state exists, derive paths from its config; otherwise use the established notes collection.

| Event | Note action | Progress action |
| --- | --- | --- |
| Explanation delivered | Add or refine the concept, source, example, and conditions | Do not claim demonstrated ability |
| Independent response | Preserve the evidence in an attempt log if one exists | Record only the tested scope |
| Mistake or misconception | Capture the actual response, failing step, correction, and a distinguishing example | Track the unresolved skill or point to its record |
| Stage check finished | Add useful new explanation; link evidence rather than copying all scores | Update the canonical plan and next action |
| New source arrives | Update source coverage and reconcile changed facts | Leave achievement unchanged |
| Learner asks a deeper question | Add the useful connection when relevant | Keep unfinished tasks visible |

Capture at meaningful boundaries while the error is still clear; do not interrupt every conversational sentence to edit files. Separate observed errors from preventive pitfalls. Avoid copying full response histories into reusable concept pages: detailed attempts belong in the log, general explanations in the notes. A progress page should link to the canonical learning plan rather than maintain its own competing status table.
